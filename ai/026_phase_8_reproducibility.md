# Phase 8 — Pipeline, testing, and reproducibility

## Goal

Turn the analytical work into a repeatable, validated build; prove stable
outputs; and complete the code-quality and hand-in checks before report writing.

## User prompts and decisions

- “Continue with Phase 8.”
- During the first two-build verification, the user chose to stop recomputing
  the daily/every-5-day/every-10-day diagnostics: “We can remove this ... and
  let it be monthly only. No real benefit to it. Can keep the comparison values
  but only build monthly walk forward. Should make things way faster.”

The second instruction changed the routine build contract. Monthly is the only
walk-forward product specification regenerated by `scripts/run_part_b.py`. The
existing faster-schedule comparison values are retained as frozen research
evidence, validated on every run, and included in reproducibility hashes.

## Implementation

- Added `src/pipeline.py` as the reusable orchestration and validation layer.
- Reduced `scripts/run_part_b.py` to a thin command-line entrypoint.
- Declared 75 canonical artifacts and 16 app-facing CSV schema contracts.
- Added controlled stale-output cleanup that preserves prototypes, manually
  reviewed lexicon research, and frozen frequency-comparison evidence.
- Added a timestamp-free manifest with relative paths, file types, byte sizes,
  CSV dimensions, and SHA-256 content hashes.
- Added `scripts/check_reproducibility.py` for two-build hash comparison, with
  optional baseline recording when builds must be split across processes.
- Added `tests/test_pipeline.py` and `pytest.ini` so tests resolve the local
  `src` package even when invoked from outside the project directory.
- Applied formatting-only lint corrections to the supplied data loader and
  hand-in checker; their behaviour was not changed.

## Errors, risks, and corrections

- The first validation heuristic treated every filename containing
  `validation` as a pass/fail table. `plain_vs_finance_validation.csv` is a
  descriptive comparison without a `status` column. The contract now lists the
  actual pass-status evidence tables explicitly.
- The initial two-build command hit the execution host's 20-minute process
  limit during the second faster-frequency pass. It raised no analytical error.
  The user then removed those slow diagnostics from the routine build.
- A full pytest invocation from `/tmp` initially failed collection because the
  local `src` package was not on pytest's path. `pytest.ini` fixed that path
  dependency, and the complete suite then passed from `/tmp`.
- The build needs the course-hosted raw-data bundle and a locally downloaded
  NLTK VADER lexicon. The deployed app still uses only precomputed artifacts
  and imports neither the build pipeline nor NLTK.
